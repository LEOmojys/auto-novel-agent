# 六维质量评审标准

每章写完后必须自评。评分 1-5，**必须附一句理由**。

| 维度 | 检查点 | 高分示例 | 低分信号 |
|---|---|---|---|
| 文风一致性 | 与前文 / project.json 风格一致 | 节奏、语气、叙述视角延续 | 突然变成另一种文风 |
| 角色一致性 | 言行符合 characters/*.json | 角色按性格说话做事 | OOC、人设崩塌 |
| 文笔流畅度 | 语句通顺、无生硬 | 读起来顺 | 病句、翻译腔、表达生硬 |
| 场景完整度 | 情节推进完整 | 场景有始有终 | 虎头蛇尾、情节断裂 |
| 对话自然度 | 符合角色口吻 | 每人的话各有特点 | 全员一个腔调 |
| 内容对齐度 | 覆盖 outline 本章 goal/beats | 大纲要点都写到 | 跑题、漏掉 beats |

## 判定规则

- **任一维 < 3** → REWRITE
- **平均 < 3.5** → REWRITE
- 全部达标 → ACCEPT

## 自评格式

```json
{
  "scores": { "文风一致性": 4, "角色一致性": 4, "文笔流畅度": 5, "场景完整度": 4, "对话自然度": 4, "内容对齐度": 5 },
  "decision": "ACCEPT",
  "reason": "各维达标；对话符合林晚的倔强性格。"
}
```

## REWRITE 流程

1. 记录失败维度 + 诊断理由（如"角色一致性=2：主角突然变得圆滑，与档案'外冷内热'不符"）
2. 带着诊断重写该章（只改问题部分，不整章推翻重写）
3. 复评；仍不达标再修（**最多 2 次**）
4. 第 3 次仍不达标 → **暂停**，告知用户，请用户决策

## 诚实原则（硬性）

- **禁止**"默认通过"——每维必须真实评分
- **禁止**为赶进度跳过审查
- 写不满意的段落要如实标低分并重写，而不是放行
