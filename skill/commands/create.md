# 新建故事流程

用户要**写一部新小说**（或"换个故事写"）时走此流程。

## 步骤

1. **确定项目名**：从需求里提炼（如"魔法学院孤儿"），目录用 `novels/<名字>/`。若项目已存在同名目录且用户要"全新故事"，**新建独立目录**，不要覆盖旧的。
2. **建目录结构**：
   ```
   <project>/
   ├── project.json
   ├── world.json
   ├── characters/
   ├── outline.json
   ├── chapters/
   ├── memory.json
   └── quality_log.json
   ```
3. **写 project.json**：标题 / 简介 / 类型 / 目标章数 / 风格。风格指南问用户或默认。
4. **写 world.json**：世界观——前提（premise）、规则、约束、关键地点。先设计世界再谈人物，避免人物与世界观冲突。
5. **设计角色**：主角 / 重要配角先建 `characters/<名>.json`；路人角色可在章节内即兴（不必提前建文件）。角色档案要写清：身份、性格、目标、特质、初始 plot_history（可空）。
6. **写 outline.json**：规划全书章节——每章 `number/title/goal/beats`。章节数默认用户要求；未指定给 10-20 章建议并询问，或默认 10。
7. **逐章写正文**：依大纲从第 1 章开始。每章：
   - 读 memory.json 确认当前状态
   - 写 `chapters/01.json`（含 body 全文 + summary + 出场角色 + 伏笔）
   - 更新 memory.json（角色变化、伏笔、已写章节号）
   - 质量审查（六维），写入 quality_log.json
8. **收尾**：更新 project.json 的 `status/progress`；汇报给用户（写了哪些章节、下一步建议）。

## 注意

- 目标章数较大的小说（>5 章）：**先完成大纲再逐章写**，中途每章都审查 + 更新记忆。
- 若一次会话写不完，告知用户当前进度，续写走 `continue.md`。
- 新手不要追求一次写完几十章——写 1-3 章示范，问用户是否继续。
