# 修订流程

用户要**修改已写内容**（"重写第 3 章 / 把女主改成反派 / 改设定"）时走此流程。

## 两种修订

### A. 单章重写
1. 定位目标章节 `chapters/NN.json`。
2. 重写正文（可基于原 goal/beats，或用户新要求）。
3. 更新该章的 `summary` / `characters` / `foreshadows`。
4. **连锁影响**：若改动影响后续章节（角色设定变了），检查并同步 memory.json，提示用户后续章节是否需要跟着改。
5. 质量审查 → quality_log.json。

### B. 设定修订（角色 / 世界观 / 大纲）
1. 改 `characters/<名>.json` 或 `world.json` 或 `outline.json`。
2. **影响评估**：列出受影响的已写章节，提示用户"这些章节可能需重写或微调"。
3. 更新 `memory.json`。
4. 询问用户：受影响章节是重写、保留（接受不一致）还是回滚到设定变更前。

## 注意
- 修订是**破坏性较小**的操作（改文件 + 同步记忆），比回滚轻。
- 角色性格/能力变更必须同步到 memory.json，否则后续章节会 OOC。
- 大改设定前，先跟用户确认影响范围。
