# 要素管理流程（世界观 / 角色 / 大纲的增删改查）

当用户**只要求对创作要素（世界观 / 角色 / 大纲）增删改查、不要求写正文**时走此流程。

## 意图判断

先确认用户说的是"要素"而非"写章节"：
- **要素请求**：加角色、改性格、删配角、补世界规则、查有哪些角色、调整大纲
- **不是要素请求**："写下一章 / 续写 / 把第 3 章写了" → 走 continue / create

若拿不准，问用户："你是想改设定，还是要写正文？"

## 路由表

| 操作 | 世界观 world.json | 角色 characters/*.json | 大纲 outline.json |
|---|---|---|---|
| **增** C | 补规则 / 地点 / 约束 | 新增 `<角色名>.json` | 生成大纲 / 追加章节规划 |
| **查** R | 读 world.json 汇总 | 列出角色 / 读单个角色 | 读 outline.json 汇总 |
| **改** U | 改规则 / 约束 / 地点 | 改角色档案字段 | 改章节 goal / beats / 顺序 |
| **删** D | 删规则 / 地点（慎） | 删 `<角色名>.json` | 删章节规划（慎） |

## 通用步骤

1. **定位项目**：`novels/<名字>/`（用户没给名字时列出所有项目或询问）
2. **操作目标**：确定是哪个要素文件
3. **执行**：按路由表操作
4. **同步 memory.json**（角色状态 / 伏笔 / 规则引用）
5. **影响评估 / 确认**（见下）
6. **汇报**：改了什么、影响范围、建议

## 三条铁律（违反即失败）

### 1. 绝不强制写章节
只做要素时，**不推进 outline → chapters**。用户说"加个反派"，你就加角色文件，**不要**顺手写一章正文。

### 2. 删除必确认 + 级联检查
删除（角色 / 规则 / 大纲章节）前，必须：
- 找出引用它的内容：`chapters/*.json` 的 characters / memory.json 的 plot_threads
- 向用户展示："删除 `林晚` 会影响第 1、3、5 章（出场）和 2 条伏笔，确认删除？"
- 用户确认后才删；并同步清理 memory.json 里的引用

### 3. 修改必做影响评估
改角色 / 世界观后：
- 列出受影响的已写章节（"改女主性格会影响第 3、4 章"）
- 问用户：受影响章节要**重写 / 保留（接受轻微不一致）/ 后续章节自动规避**？
- 改完**必须更新 memory.json**（角色状态、能力、规则引用）

## 操作细节

### 增
- **加角色**：新建 `characters/<名>.json`，按 `character.schema.json` 填全（至少 name；role/personality/goal 尽量给出，缺的让用户补充或合理设计）
- **补世界观**：往 world.json 的 rules / locations / constraints 追加
- **生成大纲**：若 outline.json 不存在或空，生成；已存在则追加章节规划（询问总章数）

### 查
- 只读，不修改任何文件
- 汇总给用户（不贴全文）

### 改
- 改后检查 schema 仍合法；改角色名时同步更新所有引用（chapters/memory/outline）

### 删
- 按铁律 2 走确认；删大纲章节 ≠ 删已写章节文件（那是 rollback.md 的职责）

## 与 create / revise / rollback 的边界

| 场景 | 走哪个 |
|---|---|
| 从零建世界/角色/大纲 | `elements.md`（增）或 `create.md`（新建整部） |
| 改已有设定 | `elements.md`（改） |
| 重写某章正文 | `revise.md` |
| 删除已写章节 | `rollback.md` |
